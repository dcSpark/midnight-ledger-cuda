# Versioned ABI contract

The crate separates stable public Rust values from private Metal dispatch
layouts. Public version-1 values may be used by application adapters; shader
records and parameter blocks remain implementation details validated at engine
startup.

## Public values

Integer limbs are little-endian. Fp and Fr Montgomery values use the BLST-
compatible residues generated by `build.rs`.

| Type | Size | Contract |
| --- | ---: | --- |
| `CanonicalScalar` | 32 bytes | Four `u64` limbs, validated `< Fr modulus` |
| `RawFrMontgomery` | 32 bytes | Four reduced Montgomery Fr limbs |
| `RawFpMontgomery` | 48 bytes | Six reduced Montgomery Fp limbs |
| `RawG1Affine` | 96 bytes | Finite x/y; preparations reject identity |
| `RawG1Jacobian` | 144 bytes | x/y/z; zero z encodes infinity |
| `MsmJobV1` | 16 bytes | Base offset, scalar offset, term count, dense output index |
| `RoutedPointV1` | 4 bytes | Bit 31 negate flag; low 31 bits base index |
| `BucketRunV1` | 16 bytes | Record offset/count, dense bucket index, zero reserved word |

All offsets, extents, products, point indices, output indices, and preparation
sizes are checked before allocation or dispatch. Public fixed windows 11 through
16 and variable windows 8 through 10 have exact window/bucket counts frozen by
unit tests.

## Engine and preparation identity

`PreparedBases` and `PreparedFixedBases` carry the creating engine context and
device registry identity. Fixed preparation also binds the public window width,
base count, expanded base count, and immutable Metal allocation. A preparation
cannot be used by another engine even on the same physical GPU.

`MetalMsmEngine` is intentionally thread-affine (`Rc`, not `Send`/`Sync`).
Synchronous submission retains every command resource through completion and
validates kernel status and erasure before returning outputs.

## Resident scalar interop

`ResidentMontgomeryScalars` is a checked retained view of a caller-owned
`MTLBuffer`. Construction binds:

- Metal device registry identity;
- storage object lifetime;
- 32-byte aligned byte offset;
- element count and checked byte extent; and
- reduced Montgomery Fr representation.

The engine validates device identity and bounds again at submission. A Metal
canonicalization pass rejects residues greater than or equal to the scalar
modulus. The command retains every source until completion. The library treats
the source as read-only and does not erase it; the producer owns source erasure
after its final consumer.

`msm_fixed_resident_sources_ragged` accepts multiple retained sources plus jobs
whose scalar offsets address their logical concatenation. The engine binds each
physical source directly and does not copy or concatenate scalar limbs on the
CPU. Job ranges may not cross source boundaries unless the API explicitly
constructs equivalent split jobs.

## Private shader ABIs

The production metallib exposes startup probes for:

- global ABI version, generated constants fingerprint, and layout fingerprint;
- XYZZ layout and status protocol;
- resident-scalar canonicalization ABI; and
- fixed-route ABI v10.

Fixed-route v10 freezes the parameter layout and production topology, including
64 threads per group, eight buckets per group, 64-bucket integration blocks,
2,048 records per long-bucket tile, and a 512-record long-bucket threshold.
Host and shader constants must match exactly.

The private path uses scalar/job, signed-record, histogram, offset/cursor,
bucket-tile, XYZZ root, integration, collection, indirect-dispatch, and atomic
status buffers. These are not zero-copy aliases of public router records. Host
translation and shader validation independently check reserved fields, dense
output layout, sorted/non-overlapping ranges, capacity, launch geometry, and
status flags.

## Compatibility rules

Any change to a public value layout requires a public ABI version review. Any
change to a shader parameter/record layout, status meaning, fixed topology, or
generated curve constant requires the corresponding private ABI/fingerprint
update and negative compatibility tests.

Adding writable resident views, external command events, asynchronous return,
or cross-engine preparation sharing is not a compatible extension. Such a
surface must define aliasing, producer/consumer synchronization, cancellation,
completion, and erasure ownership before it can be exposed.

`--features metal` compiles the production shader root. The separate
`metal-diagnostics` root may contain historical experiment ABIs; those are not
accepted by the production proof build.
